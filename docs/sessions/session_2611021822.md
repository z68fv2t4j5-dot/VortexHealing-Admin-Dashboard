# Session 2026-11-02 18:22 - Zoom transcripts pulled by a tested command in this repository

**Type:** feature. **Branch:** feat/zoom-sync. **Work item:** none. **Plan:** `docs/plans/PLAN-zoom-sync-2611021715.md`.

## Summary of actions

Daniel asked for the transcription project to run under this harness and chose this repository over a new one. The first Zoom import had run from loose scripts in the transcripts folder (four downloader variants, a hard-coded folder and account address, no tests). Planned and built `backend/transcript_import/zoom.py` with a CLI, `python -m transcript_import zoom [--dry-run]`: it lists the last six months of meeting instances through the report API, skips UUIDs already in the import manifest, downloads each remaining transcript, converts it to Markdown in the existing format, and files it into the one non-underscore subfolder of `ZOOM_FOLDER` that already holds the topic, else `_inbox/`. Three optional settings (`ZOOM_CREDENTIALS`, `ZOOM_USER_ID`, `ZOOM_FOLDER`) were added to `Settings` and `.env.example`, and set in Daniel's local `backend/.env` without reading the file. The one-off history-import scripts stay in the local import folder.

Investigation while planning found that the first import's 436 downloaded files hold 279 distinct transcripts: the portal lists some meetings twice, the API returns one transcript per UUID, and the earlier runs saved it under two or three names. The Zoom teacher folder holds 89 byte-identical extra copies (counted by hashing bodies; no content read). Reported to Daniel; nothing moved.
