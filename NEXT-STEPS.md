## Traps, in the order they will bite

1. `python3` must be 3.11+; on this Mac that relies on `~/.local/bin` being first on PATH (set in `~/.zshrc`).
2. Every new key in `backend/.env` needs a field on `Settings` in `backend/app/core/config.py` first; that class forbids unknown keys and the whole backend fails to start.
3. The dashboard backend runs on port 8001, because Daniel's finances app uses 8000. Pages must call relative `/api` URLs; a hard-coded `localhost:8000` reaches the wrong app.
4. LM Studio: load `qwen/qwen3.8-27b` at 49152 context and `text-embedding-nomic-embed-text-v1.5`; without the embedder, search falls back to keywords. Load it as the MLX file `qwen/qwen3.8-27b@4bit` (the login item and the page's "Load models" do); call it by that exact identifier: `qwen3.8-27b` without `qwen/` made LM Studio load a second, slower copy (`lms ps` shows it; `lms unload qwen3.8-27b` removes it). In Continue, Qwen needs `maxTokens: 12000` and `reasoning_effort: low` or it spends its whole reply thinking.
5. Never commit a check that reads real student data or handout text; run it outside the repository and record only counts.
6. Changing a model does not change its existing table; back up `backend/vortexhealing.db` and rebuild the table.
7. Zoom transcripts: the UUID is the identity, never the file name, and Zoom's report API reaches back six months only; older transcripts came from the portal through one-off scripts left in the local `zoom-import` folder. Never print or read the credentials file.
8. CI installs `backend/requirements-test.txt` only: a test that imports a router importing `app/schemas.py` needs `email-validator` there (added 2026-11-04). Check new imports against that file before pushing.
9. `NTFY_TOPIC` is a secret (anyone with it reads the digests): never print it, log it or put it in a commit, session log or transcript. It is also the `vortexhealing` line of `~/.config/notify/topics`; rotating it means changing both and resubscribing the phone.
10. Two clocks: reminder dates are Sydney dates; admin tasks, hand-added tasks and the 09:00 digest are Amsterdam. A digest sent after 14:00-16:00 Amsterdam already counts reminder days by Sydney's next date.
11. The digest job runs whatever is checked out in this working tree. A branch made before 506df1e (2026-11-06) has no `app/digest.py`, so while it is checked out every hourly run fails and Daniel gets a "Digest failed" alert. Rebase such a branch onto main before checking it out.
12. No alert on the phone: first ask ntfy.sh whether it holds the message, in Python with `settings.NTFY_TOPIC` and `GET {NTFY_SERVER}/{topic}/json?poll=1&since=2h`, printing titles only, never the topic. On 2026-11-06 the server held it and the phone's subscription was mistyped.
13. `backend/app/class_lists.py` needs `openpyxl` (in both requirements files since 2026-11-12). A backend venv made before that fails to start with `No module named 'openpyxl'`: `cd backend && venv/bin/pip install openpyxl==3.1.5`.
